# Dojo Video Engine 1.1 source-candidate report

Date: 2026-08-26  
Status: repository source candidate; npm publication and Git tag not claimed

## Outcome

Dojo Video Engine 1.1 completes the post-1.0 engine roadmap without replacing Scene
v1 or introducing a second renderer contract. The tested path is:

```text
strict Scene document
  → typed reversible command
  → spatial, temporal, and audio inspection
  → reusable prepared runtime and display list
  → deterministic Canvas preview/export
  → bounded proof and verification evidence
```

All 16 public packages use version `1.1.0`. The repository additionally ships
an optional provider-neutral Agent Skill, a thin private MCP adapter, common
timeline interchange, trusted-host Remotion interoperability, a sanitized
static-snapshot bridge, and macro/extension/repair examples.

## Reproducible candidate

Run:

```sh
pnpm install --frozen-lockfile
pnpm check:contracts
pnpm audit --prod --audit-level high
pnpm release:full
node scripts/pack-release.mjs /path/to/empty/release-directory
RELEASE_VERSION=1.1.0 node scripts/publish-release.mjs \
  /path/to/empty/release-directory --verify-only
node scripts/verify-clean-machine.mjs \
  --pack-dir /path/to/empty/release-directory
```

The bundler writes exactly one tarball for every public package, SHA-256 and
SHA-512 SRI, the frozen lockfile, a 16-root lock-aware CycloneDX graph, license
and zero-high/critical audit evidence, a v2 release manifest, and
`SHA256SUMS`. The clean verifier consumes that directory without repacking and
exercises Node/ESM, authoring, workflow, interchange, browser, worker, CLI, and
build paths. The protected publisher preflights immutable registry integrity,
stages only missing packages under a temporary tag, verifies the complete set,
then promotes `latest` and attaches the exact bundle to the GitHub release.

## Publication boundary

This source tree and changelog do not prove that a registry version or Git tag
exists. A maintainer must follow [`release-process.md`](release-process.md),
verify package ownership and protected-environment approval, publish the exact
tested tarballs, retain provenance/SBOM receipts, create the annotated tag, and
record the resulting URLs. Until those receipts exist, source-checkout commands
are authoritative and registry commands remain explicitly conditional.
