# Dojo Video Engine 1.1 compatibility report

Status: source candidate; npm/tag receipts absent
Date: 2026-08-26

## Preserved

- Scene v1 remains the low-level render document; valid 1.0 scenes retain
  timing/layout/pixels/audio.
- Legacy stateless agent tools, Canvas renderer/player/export facades,
  extension legacy adapters, preset/macro outputs, and CLI commands remain.
- Full legacy pinned-browser hashes, audio/video export checks, and migration
  corpus pass unchanged.

## Additive

- strict repair/preflight grammar and media lifecycle hardening;
- inspection, commands/workspace, prepared runtime, display-list contracts;
- Layout Contract v1 in `@dojo-video-engine/layout`;
- handle workflows/proof evidence and three new command kinds;
- `@dojo-video-engine/interchange` timeline/trusted-host bridges;
- scoped `@dojo-video-engine/create` package identity while retaining the
  `create-dojo-video-engine` bin.

## Deliberate package-name correction

The repository-only unscoped `create-dojo-video-engine` identity conflicts with an
unrelated npm package. The 1.1 candidate uses `@dojo-video-engine/create`. No valid
external 1.0 package is being removed; generated project structure and bin
behavior remain compatible. See
[`../migrations/1.0-to-1.1.md`](../migrations/1.0-to-1.1.md).

## Interchange losses

Timeline and static snapshot bridges return explicit loss diagnostics. They do
not execute/import arbitrary React, scripts, dynamic CSS layout, expressions,
or browser state. Remotion interoperability is a trusted host descriptor, not
an arbitrary component translator.

Verification:

```sh
pnpm corpus:check
pnpm check:migrations
pnpm golden:test
pnpm check:contracts
```
