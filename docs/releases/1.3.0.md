# Dojo Video Engine 1.3.0 source candidate

This synchronized 17-package candidate adds `dataChart` to the presets
registry and the commands capability manifest. The latest verified publication
in this repository is [1.2.3](1.2.3.md); this note is not a tag, registry or
downstream adoption receipt.

## Compatibility and use

- Supply one ordered series of two to eight label/value pairs, an explicit unit,
  and a finite increasing numeric domain that contains all values. Bars require
  the domain to include zero. The macro rejects multiline labels or units and
  labels that exceed its layout budget. The [presets example](../../packages/presets/README.md) shows a signed
  bar chart.
- Expansion produces ordinary editable Scene v1 nodes. Line markers and their
  polyline share a reveal boundary; signed bars grow in opposite directions
  from the same baseline. Category spacing is uniform. Multiple series and
  irregular numeric/time spacing are outside this macro's contract.
- Existing Scenes need no migration. A consumer that authors the macro must
  install a version that advertises it; a consumer displaying the expanded
  Scene needs only its existing native primitives. An expanded label is plain
  text: changing it alone does not change the underlying plotted geometry.
- A host replaying an older authoring session can set `MacroContext.allowedMacroNames`
  to its saved vocabulary. The same restriction applies to nested expansion
  and suggestions for unrecognized names. Omitting the option uses the installed registry.
- Scene schema, renderer, extension ABI and package entry points are unchanged.
  The starter's output now points to the renamed Dojo Video Agent repository.

## Candidate verification

The [full engine gate](../testing-strategy.md) runs the chart browser regression.
It seeks a portrait line chart and a landscape signed-bar chart and checks
their geometry through the reveal in independently decoded MP4 frames. Preset
unit tests exercise bad domains, data outside the domain, zero-baseline rules
and labels that cannot fit. These checks establish fixture behavior, not
creative quality for arbitrary input.

For registry publication and consumer upgrades, follow the
[release process](../release-process.md): qualify the reviewed source commit,
verify the release tag, retain and validate the exact artifacts, and record
registry integrity and provenance before changing downstream pins.
