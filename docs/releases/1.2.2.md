## Behavior and compatibility

The default `maxLines` for native text-overlay slots now preserves the number of
authored newline-separated lines. This applies to title cards, lower thirds,
quote cards, stat callouts, announcement banners, social hooks and chapter titles.
Explicit caller `maxLines` overrides still win. Text-box fitting and ellipsis
behavior remain unchanged; this patch does not guarantee arbitrary copy fits.

The fix is source commit `3e753c8006de4ec8c7fe14940a07377eedecd936` and includes
per-slot and macro regressions plus the rendered `title-card-three-line-subtitle`
probe. Scene v1, package APIs, extension contracts and source-clock semantics are
unchanged. Both consumers should adopt exact immutable release bytes; do not use
engine source aliases or restore a vendored renderer.

## Signing recovery and remaining limits

The original tag job stopped before signing when GitHub's direct Gitsign asset
download returned HTTP 504. The separate [workflow repair](https://github.com/PansaLegrand/dojo-video-engine/pull/7)
downloads the same official, checksum-pinned binary through GitHub's release API.
Its macOS/Linux CI passed before merge. The successful signer used that repaired
main workflow while preserving the qualified source commit above; no tag was
moved and no package version was reused.

A separate small-canvas preset defect remains: a bold title-card macro on a
640×360 canvas can produce a zero-height title layout when fixed padding consumes
the plate. This patch preserves explicit text lines; it does not repair that plate
geometry. Consumers should reject zero-area graphic text and allow a corrected
layout before committing. Arbitrary copy fitting and visual acceptance remain
separate checks.

## Consumers

Both the open-source harness and commercial web application should consume exact
1.2.2 registry versions and retain the final manifest and lockfile integrity.
Publication does not by itself prove either consumer has adopted or deployed the
new package set. Engine source aliases and vendored renderer copies remain
unsupported.
